# Product

Product context. Start with `context.md`: North Star, pillars, baselines, and which tool answers what. Every strategy, cadence, and analysis skill reads it first.

## Subfolders

| Folder | What's in it | When to read |
|--------|-------------|--------------|
| `analytics/` | Metric definitions, BigQuery reference, funnel stages, data quality log | Any data or metrics question |
| `roadmap/` | Roadmap, current bet, betting table, experiments, annual strategy | Sprint priority, what's next, strategic direction |
| `specs/` | Index of specs (most live in Google Docs) | Looking for a feature spec or design doc |
| `playbooks/` | PM toolkit, evidence loop, ticket guidelines | Need a PM method the skills cite |
| `analysis/` | Dated skill outputs (strategy, audits, data, premortems, evals) | Citing a past analysis |
| `reference/` | Industry research, pricing, PM principles | Background reading, standards, mental models |
| `customer-insights/` | Captures from customer calls, support, and user research | Designing experiments, writing specs, monthly retros |
| `signals/` | Inbox where alerts, support exports, and reviews land as dated files; `/triage` and the `metric-breach` run read them | Before triage, or to see what the drop contract expects (`signals/CLAUDE.md`) |
