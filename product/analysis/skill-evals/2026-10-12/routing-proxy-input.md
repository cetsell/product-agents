# Skill listing (name: description + when_to_use)

- **ab-test-setup**: Turns a proposed change into a pre-registered A/B test plan: hypothesis, control and variants, primary, secondary, and guardrail metrics, minimum detectable effect, sample size, duration, and decision rule. Reads out results against that rule, and on request logs the test to the experiment roadmap. Use when the user mentions "A/B test", "split test", "experiment", "test this change", "hypothesis", "should I test this", "which version is better", "statistical significance", or "how long should I run this test", and whenever /page-cro, /signup-flow-cro, /popup-cro, /onboarding-cro, /paywall-upgrade-cro, or /pricing-strategy hands off a change to prove. Not for generating the change ideas (use those skills) or writing variant copy (use /copywriting).
- **audit**: Operational and product health audits built on multi-week data: velocity and blocker archaeology (operational lens), shipped-to-activated lag (product lens), bet post-mortems that compare hypothesis to result, and process audits that find where handoffs lose days. Findings carry dated sources and an owner. Use for "audit", "health check", "operational review", "product review", "are we shipping to learn", "what's slipping", "shipped to activated", "post-mortem", "did the bet pay off", "benefits realization", "process audit", "where are handoffs breaking", "bottleneck". For a single metric or funnel question use /data-analyst; for a sprint sweep use /sprint-health.
- **cadence**: Runs the PM's weekly and monthly operating rhythm: Monday kickoff, Wednesday pulse, Thursday prep, Friday demo-and-decide, weekly team update, stakeholder update, and monthly recap. Each mode pulls shipped work, the current bet, and meeting notes, then writes a dated note that forces an iterate-or-swing call on the bet. Use when the user says "monday kickoff", "wednesday pulse", "thursday prep", "friday demo", "week in review", "weekly update", "team update email", "stakeholder update", "exec update", "monthly recap", "investor update", or a day-of-week plus report keyword ("monday report", "friday summary").
- **check-artifacts**: Grades the team's planning artifacts A–F for freshness, specificity, and alignment with the issue tracker: roadmap, betting table, current bet, baseline metrics in product/context.md, and tracker initiatives and milestones. Returns a prioritized fix list so decisions are made on current information. Use for "check artifacts", "artifact health", "are my artifacts up to date", "grade my roadmap", "what's stale", "do I have it handled", or before a leadership review, planning session, or Friday decide.
- **churn-prevention**: Diagnoses where a subscription product is losing customers (voluntary vs. involuntary, by cohort and cancel reason) and produces a prioritized churn plan for one surface: cancel flow, save offers, proactive retention, dunning, or win-back, each recommendation tied to the churn metric it should move and the test that proves it. Use when churn is too high or the user wants a cancel flow, save offer, exit survey, pause option, dunning or failed-payment recovery, churn health score, or retention plan. Triggers: "churn," "cancel flow," "save offer," "dunning," "involuntary churn," "customers are leaving," "how do I keep users." Not for win-back email copy (use /email-sequence), in-app upgrade paywalls (use /paywall-upgrade-cro), or activation of new users (use /onboarding-cro).
- **copywriting**: Writes new conversion copy for marketing pages (homepage, landing, pricing, feature, about) and edits existing copy with the Seven Sweeps pass. Returns paste-ready copy by section, headline and CTA alternatives with rationale, the conversion metric the page should move, and the A/B test that would prove the new copy beats the old. Write mode: "write copy for", "rewrite this page", "marketing copy", "headline help", "CTA copy". Edit mode (copy already exists): "edit this copy", "review my copy", "copy feedback", "proofread", "polish this", "make this better", "copy sweep", "tighten this up", "reads awkwardly", "too wordy", "sharpen the messaging". Not for page structure or layout (use /page-cro), email copy (use /email-sequence), popup copy (use /popup-cro), or test design (use /ab-test-setup).
- **data-analyst**: Answers product questions with sourced numbers from the team's data warehouse (BigQuery by default): conversion funnels, growth trends, activation, monetization, device and acquisition-source breakdowns, and data-quality checks. Without a warehouse connection it writes the SQL for the user to run and continues from the pasted results. Use for "funnel audit", "conversion analysis", "where are users dropping", "growth trends", "cohort analysis", "device breakdown", "acquisition source ROI", "weekly metrics", "revenue analysis", "data quality check", or any question that needs a number from the warehouse. Not for multi-week operational audits (use /audit).
- **email-sequence**: Designs or optimizes one automated email sequence (welcome, nurture, onboarding, re-engagement, upgrade, dunning, win-back, or campaign): trigger, exit conditions, timing, full copy per email, and the metric each email and the sequence must move. Use when the user wants an email sequence, drip campaign, nurture or welcome series, onboarding emails, re-engagement or win-back emails, lifecycle or triggered emails, or an audit of their email program. Triggers: "email sequence," "drip campaign," "nurture sequence," "onboarding emails," "lifecycle emails," "email automation." Not for in-app onboarding (use /onboarding-cro), cancel flows and payment retry logic (use /churn-prevention), or the landing pages emails link to (use /copywriting).
- **eval-runner**: Scores prompt or model variants for an AI feature against a labeled dataset and the pass bar in its eval-requirements doc, using an explicit, configurable LLM judge. Reports pass rate per variant, judge-human agreement, and a ship / runner-up / kill call. Use for "run evals", "eval this prompt", "compare prompts", "which variant is better", "test these variants", "score these outputs", "what's our pass rate", "check judge agreement". Not for evaluating team-os skills (use /skill-eval).
- **evidence-loop**: Pressure-tests a consequential output before it drives a decision. Produces a claim-by-claim appraisal: what is claimed, what a dated source actually supports, the one assumption that would flip the decision, and where a human must decide. Use for "evidence loop", "how do we know", "pressure-test this", "what's this based on", "audit these claims", "is this supported", "check my reasoning", or before a strategy call, PRD, audit finding, or metric goes to a stakeholder. Method: product/playbooks/evidence-loop.md.
- **issue-creator**: Turns product intent (an idea, bug report, chat message, or PRD excerpt) into a ticket an engineer can start on in ten minutes: problem with a number, testable acceptance criteria, hypothesis and kill trigger, analytics plan, and explicit scope. Splits epics into 1–3 day tickets and proposes them for approval. Linear by default; adapts to Jira or GitHub Issues. Use for "make a ticket for", "create an issue", "write up a Linear issue", "turn this into a ticket", "spec this out as a ticket", "I need an issue for the team", "break this epic into tickets", or a pasted message or PRD excerpt that should become engineering work. For a full PRD use /pm-super-agent.
- **marketing-psychology**: Names the behavioral mechanism behind a proposed product or marketing change (from a catalog of 70+ mental models and biases) and turns it into a falsifiable test hypothesis ready for /ab-test-setup. Returns a short mechanism card: the behavior, the model, why it should apply here, the hypothesis, the metric it moves, and the ethics check. Use when someone proposes a change and asks "why would this work", "what's the psychology here", "which bias applies", "is this a dark pattern", or mentions anchoring, social proof, loss aversion, scarcity, defaults, friction, or persuasion. Also use to explain a surprising test result. Not for designing the test itself (use /ab-test-setup), writing the copy (use /copywriting), or setting prices (use /pricing-strategy).
- **marketing-strategy-pmm**: Produces one product marketing artifact per run: a positioning document (April Dunford method), a messaging hierarchy, a tiered launch plan, or a competitive battlecard. Each artifact names the metric it should move, its baseline, and the test that would prove it, and is written to product/analysis/strategy/. Use when the user says "position this", "positioning", "messaging", "value prop", "launch plan", "GTM", "go-to-market", "battlecard", "how do we beat X", "competitive positioning", or "win/loss". Not for overall product strategy or prioritization (use /strategy), pricing and packaging (use /pricing-strategy), or writing final page and email copy (use /copywriting, /email-sequence).
- **monthly-pm-self-eval**: Monthly, evidence-based PM self-evaluation. Scores decision quality, hypothesis discipline, kill rate, communication, and speed from the decision log, Friday notes, and issue-tracker data, then names one behavior to change next month. Run on the first working day of the month, or when the user says "monthly eval", "self-eval", "PM review", "how am I doing", "kill rate", or "decision quality review".
- **onboarding-cro**: Audits post-signup onboarding: activation definition, first-run flow, checklists, empty states, tours, onboarding emails, and stalled-user recovery. Returns a ranked list of changes, each with the metric it should move, expected direction, confidence, and the A/B test to prove it, plus an onboarding flow design when asked. Use when the user mentions "onboarding flow", "activation rate", "first-run experience", "empty states", "onboarding checklist", "aha moment", "users aren't activating", "nobody completes setup", "users sign up but don't use the product", "time to value", or "first session experience". Not for the signup form itself (use /signup-flow-cro), writing the email series (use /email-sequence), or paid conversion (use /paywall-upgrade-cro).
- **page-cro**: Audits marketing pages (homepage, landing, pricing, feature, blog) and the lead, demo, and contact forms on them. Returns a ranked list of changes across value prop, headline, CTA, hierarchy, trust, objections, and friction, each with the metric it should move, expected direction, confidence, and the A/B test to prove it, plus copy alternatives for the top change. Use when the user says "CRO", "this page isn't converting", "improve conversions", "my landing page sucks", "low conversion rate", "bounce rate is too high", "people leave without signing up", or shares a page URL and asks for feedback. Not for signup flows (use /signup-flow-cro), post-signup activation (use /onboarding-cro), popups (use /popup-cro), in-app upgrade screens (use /paywall-upgrade-cro), or a full copy rewrite (use /copywriting).
- **paywall-upgrade-cro**: Audits in-app paywalls, upgrade screens, upsell modals, feature gates, usage-limit and trial-expiration screens. Returns the trigger point, current vs. recommended screen components, and a ranked list of changes, each with the metric it should move, expected direction, confidence, and the A/B test to prove it. Use when the user mentions "paywall", "upgrade screen", "upsell", "feature gate", "convert free to paid", "freemium conversion", "trial expiration screen", "limit reached screen", "free users won't upgrade", "trial to paid conversion", or "how do I get users to pay". Not for public pricing pages (use /page-cro), what to charge (use /pricing-strategy), or cancel and save flows (use /churn-prevention).
- **pm-super-agent**: Turns a raw product idea, notes dump, or transcript into a buildable PRD with a hypothesis, kill trigger, and confidence level, then decomposes it into 1–3 day tickets proposed for approval. For AI features the PRD becomes an eval-requirements doc. Covers context hunt, intake, refinement, PRD, diagrams, decomposition, and retro. Use for "PRD", "spec", "feature idea", "product requirement", "help me think through", "scope this", "break this down", "what should we build for X", "refine this idea", "make this buildable", "write requirements for", or pasted notes or transcripts that need to become structured product work. For a single ticket use /issue-creator; for ranking several ideas use /strategy.
- **popup-cro**: Audits and designs popups, modals, slide-ins, exit-intent overlays, and announcement banners. Returns a ranked list of changes (trigger, targeting, offer, copy, frequency), each with the metric it should move, expected direction, confidence, and the A/B test to prove it, plus a popup spec when designing a new one. Use when the user mentions "popup", "exit intent", "modal", "lead capture popup", "email popup", "announcement banner", "overlay", "slide-in", "scroll trigger", "sticky bar", or "collect emails with a popup". Not for the page around the popup (use /page-cro), signup forms (use /signup-flow-cro), or in-app upgrade modals (use /paywall-upgrade-cro).
- **premortem**: Runs a premortem on a plan, launch, bet, pricing change, hire, or strategy: assumes it failed six months from now, investigates each failure reason in parallel, and returns the most likely and most dangerous failures, the hidden assumption, a revised plan, and a pre-launch checklist. Use for "premortem this", "run a premortem", "what could kill this", "stress test this plan", "find the blind spots", "what am I missing", "poke holes in this", "where will this break", or when a new high-stakes bet enters the betting table. Not for simple feedback on a draft or factual questions.
- **pricing-strategy**: Designs and reviews pricing: value metric, tier structure and packaging, price points, price increases, and the research or test that would validate them. Writes a pricing recommendation that names the revenue metric it should move, its guardrail, and the validation plan. Use when the user mentions "pricing", "pricing tiers", "freemium", "free trial", "packaging", "price increase", "value metric", "Van Westendorp", "willingness to pay", "monetization", "how much should I charge", "per seat pricing", "annual vs monthly", or "should I offer a free plan". Not for in-app upgrade screens (use /paywall-upgrade-cro), pricing page conversion (use /page-cro), or cancel flows (use /churn-prevention).
- **programmatic-seo**: Designs SEO pages at scale from a template plus a data set: picks the playbook (templates, comparisons, integrations, locations, personas, and more), defines the keyword pattern, data model, page template, linking and indexation plan, and a sample of generated pages, with the organic metric the pages should move and how a staged rollout proves it. Use for "programmatic SEO", "pSEO", "template pages", "pages at scale", "directory pages", "location pages", "[keyword] + [city] pages", "comparison pages", "integration pages", "generate 100 pages", "data-driven pages", "templated landing pages", or any plan to build many similar pages targeting different keywords. Not for the copy on one page (use /copywriting), conversion of a single page (use /page-cro), or positioning for comparison pages (use /marketing-strategy-pmm).
- **referral-program**: Designs or optimizes one customer referral or affiliate program: the trigger moment, share mechanism, incentive structure, attribution and fraud guards, and the metric and test that show whether the loop is lowering blended CAC. Use when the user wants existing customers or partners to bring in new customers. Triggers: "referral," "refer a friend," "affiliate," "ambassador," "word of mouth," "viral loop," "partner program," "referral incentive," "affiliate payout," "customers referring customers." Not for the referral email copy itself (use /email-sequence) or the referred-user landing page (use /page-cro or /copywriting).
- **senior-prompt-engineer**: Production prompt engineering for AI product features: audit an existing prompt, design a new one, make structured output reliable, or debug a misbehaving surface. Every proposed change ships as an exact diff plus the eval cases that must pass before it goes live. Use for "audit this prompt", "improve this system prompt", "design a prompt for", "the model keeps returning bad JSON", "structured output", "why is the model doing X", "prompt debug", "token budget". To score variants against a dataset, hand off to /eval-runner.
- **signup-flow-cro**: Audits signup, registration, account-creation, and trial-start flows. Returns a ranked list of changes (fields, steps, auth options, trust, errors, post-submit), each with the metric it should move, expected direction, confidence, and the A/B test to prove it, plus a redesigned field set when asked. Use when the user mentions "signup conversions", "registration friction", "free trial signup", "reduce signup dropoff", "account creation flow", "people aren't signing up", "signup abandonment", "too many steps to sign up", or "simplify our signup". Not for post-signup activation (use /onboarding-cro), the landing page before signup (use /page-cro), or popup lead capture (use /popup-cro).
- **skill-eval**: Behavioral eval for the team-os skill library. Runs a skill against representative prompts and scores the output on five dimensions (stayed in role, wrote into the shape, terminated, evidence loop, triggered correctly), then writes a dated scorecard with one verdict. Use for "eval this skill", "skill eval", "is this skill any good", "test the skill", "did the skill drift", "benchmark the skill". For the static file check run `node check-skills.mjs`; to score an AI product feature use /eval-runner.
- **sprint-health**: Sprint health sweep: ticket quality, staleness, done-to-in-progress ratio, regression risk, orphan bets, and escalations, with launch-readiness gates when a launch is within four weeks. Ends in a ranked action list where every flag has an owner. Use for "sprint health", "velocity check", "blocker scan", "what's stuck", "launch readiness", "go/no-go", "are we ready to launch", or before a Monday kickoff or Thursday prep. Not for multi-week trend audits (use /audit).
- **strategy**: Sharpens product bets: RICE/ICE prioritization, opportunity trees and metric trees, competitive analysis through 7 Powers, OKR cascades, quarterly vision checks, and decision memos. Every output ends in a ranked call with the assumption that would flip it. Use for "prioritize", "RICE", "ICE", "what should we build next", "rank these bets", "OKRs", "cascade goals", "competitive analysis", "competitor just launched", "7 powers", "opportunity tree", "metric tree", "discovery", "quarterly planning", "vision check", "decision memo", "tradeoff". Not for writing a PRD (use /pm-super-agent) or tickets (use /issue-creator).
